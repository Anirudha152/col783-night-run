Pixels, sampling and interpolation

    Pre-minorDeck 02

    A digital image is a grid of numbers

    A real scene is a smooth function \(f(x, y)\). A camera turns it into a grid. Two things happen.

    • Sampling: we only keep the value at grid points. This decides the resolution (M × N pixels).
    • Quantization: we round each value to one of \(L\) levels. Usually \(L = 2^k\). With \(k = 8\), we get 256 levels.

    Storage for an M × N image with \(k\) bits per pixel: \(M N k\) bits. A colour image has 3 channels, so \(3MNk\).

    Interpolation: finding values between pixels

    When we zoom or rotate, we need \(f\) at points that are not on the grid. Guessing those values is interpolation.

    • Nearest neighbour: copy the closest pixel. Fast, but blocky.
    • Linear (1D): draw a straight line between the two nearest samples.
    • Bilinear (2D): do linear along \(x\), then linear along \(y\). Order does not matter.
    • Bicubic: same idea with cubic curves, using 4 × 4 pixels. Smoothest.
    \[ f(x) = (1-t)\,f[i] + t\,f[i+1], \qquad i = \lfloor x \rfloor,\; t = x - i \]

    Weight of each corner = area of the opposite rectangle. The 4 weights add to 1.

    Worked example: zoom 3 × 3 to 5 × 5

    Image arithmetic and linearity

    • Averaging n noisy photos of the same scene cuts noise. Noise std drops by \(\sqrt{n}\).
    • Subtracting before/after images shows what changed.
    • Dividing by an illumination estimate gives reflectance: \(r = f / i\).
    Overflow trap. In 8-bit unsigned maths, \(130 + 140 = 14\) and \(130 - 140 = 246\). Compute in float or 16-bit, then clip back to [0, 255].

    An operation \(H\) is linear if \(H(af + bg) = aH(f) + bH(g)\).

    • Sum of all pixels: linear.
    • Max of all pixels: not linear. Example: \(f = [1, 0]\), \(g = [0, 1]\). \(\max(f+g) = 1\), but \(\max f + \max g = 2\).

    Geometric transforms: always map backwards

    To rotate or scale an image by a map \(T\):

    • Forward (bad): send every input pixel to \(T(x,y)\). Some output pixels get nothing, so you see holes.
    • Reverse (good): for every output pixel, find where it came from, \((x, y) = T^{-1}(x', y')\), and interpolate \(f\) there.

    Most transforms used are affine: \([x'\ y'\ 1]^T = A\,[x\ y\ 1]^T\) with a 3 × 3 matrix whose last row is \([0\ 0\ 1]\). This covers scale, rotate, shear, translate.

    You have 1 clean shaded image and \(n\) noisy illumination estimates \(i_k\). Should you average the \(i_k\) first and then divide, or divide by each and then average?
    Answer

    Average first. Averaging is linear, but division by \(i\) is not linear in \(i\). Dividing by a noisy \(i_k\) blows up noise wherever \(i_k\) is small. Averaging first gives a clean \(\bar i\), then \(r = f/\bar i\).

    Intensity transforms and histograms

    Pre-minorDeck 03, 04

    Point operations: one pixel at a time

    An intensity transform maps each pixel value \(r\) to a new value \(s = T(r)\). It ignores neighbours. You can store \(T\) as a lookup table.

    • Negative: \(s = L - 1 - r\).
    • Brightness / contrast: \(s = c(r - k) + k\). Contrast up if \(c > 1\).
    • Log: \(s = \log(1 + r)\). Squashes a huge range. Used to display Fourier spectra.
    • Gamma: \(s = r^\gamma\) on [0, 1]. \(\gamma < 1\) brightens darks. \(\gamma > 1\) darkens.
    Rule. \(T\) should be increasing. If not, ordering of intensities flips and you get odd inversions.

    Contrast stretching and thresholding

    Where the curve is steep, nearby input values get pushed apart: more contrast. Where it is flat, they get squashed together.

    Thresholding is the extreme case: output is only 0 or 1.

    The histogram

    \(h(r)\) = how many pixels have value \(r\). Normalized: \(p(r) = h(r)/MN\). So \(p(r)\) is the chance a random pixel has value \(r\).

    \[ m = \sum_r r\,p(r), \qquad \sigma^2 = \sum_r (r - m)^2\,p(r) \]

    A narrow histogram means low contrast. Spreading it out improves contrast.

    Histogram equalization

    Goal: make the histogram as flat as possible. The trick: use the CDF as the transform.

    \[ s_k = T(r_k) = (L-1)\sum_{j=0}^{k} p(r_j) \]

    Why it works: if \(s = (L-1)\,\mathrm{CDF}(r)\), then the CDF of \(s\) is a straight line. A straight-line CDF means a flat histogram.

    Local equalization and CLAHE

    • Local histogram equalization: for each pixel, equalize using only the histogram of a window around it. Brings out local detail.
    • Fast version: compute \(T\) per block, then interpolate between nearby blocks' \(T\)s.

    Problem: the slope of \(T\) is \(T(r) - T(r-1) = (L-1)\,p(r)\). In a flat region the histogram has a tall spike, so the slope is huge. Noise gets amplified.

    CLAHE = Contrast Limited AHE. Clip the histogram at a max height. Spread the clipped pixels evenly over all bins. This caps the slope, so it caps the contrast boost.

    Exam-style practice

    A 2-bit image (L = 4) has 16 pixels with counts \(h = [8, 4, 4, 0]\). Find the equalization map.
    Answer

    \(p = [.5, .25, .25, 0]\). CDF \(= [.5, .75, 1, 1]\). Multiply by 3: \([1.5, 2.25, 3, 3]\). Round: \(0\to2\) (1.5 rounds to 2), \(1\to2\), \(2\to3\), \(3\to3\).

    Note 0 and 1 merge. Histogram is not flat, which is expected.

    Is histogram equalization idempotent (does applying it twice change anything)?
    Answer

    In the continuous case, yes: the output is already uniform, so its CDF is a straight line and \(T\) is the identity. In the discrete case it is (almost) idempotent too: the second pass maps each occupied level to itself or very close.

    Shapes are sets of pixels

    A binary image is just a set \(A\) of foreground pixels. Morphology changes shapes using a small probe shape called the structuring element (SE), \(B\). Think of \(B\) as the "kernel" of morphology.

    Chaining. \((A \oplus B) \oplus C = A \oplus (B \oplus C)\). Dilation is associative. So two dilations by 3 × 3 and 5 × 5 boxes = one dilation by a 7 × 7 box. Same for erosion: \((A \ominus B)\ominus C = A \ominus (B \oplus C)\).

    Opening and closing

    Erosion then dilation does not give back \(A\). What it gives is useful:

    \[ A \circ B = (A \ominus B) \oplus B \qquad A \bullet B = (A \oplus B) \ominus B \]
    • Opening = union of all copies of \(B\) that fit inside \(A\). Removes small objects, thin bridges and spikes. Rounds outward corners.
    • Closing = complement of the union of copies of \(B\) that fit in the background. Fills small holes and thin gaps.

    Properties to quote in proofs

    • Duality: \((A \circ B)^c = A^c \bullet \hat B\).
    • \(A \circ B \subseteq A \subseteq A \bullet B\).
    • Monotone: \(C \subseteq D \Rightarrow C \circ B \subseteq D \circ B\).
    • Idempotent: \((A \circ B) \circ B = A \circ B\). Opening twice does nothing new.

    Quiz 3 Q1, solved

    B and C are 3 × 3 and 5 × 5 boxes. Is there D with \((A\oplus B)\oplus C = A \oplus D\) for all A? Is there E with \((A \circ C)\circ B = A \circ E\) for all A?

    Part 1: yes, D = 7 × 7 box

    Dilation is associative: \((A\oplus B)\oplus C = A \oplus (B \oplus C)\). And \(B \oplus C\) = 3 × 3 box grown by 2 on every side = 7 × 7 box.

    Part 2: yes, E = C

    1. \(A \circ C\) is a union of copies of \(C\) (by definition of opening).
    2. Each 5 × 5 box is itself a union of 3 × 3 boxes. So \(C \circ B = C\).
    3. So \(A \circ C\) is a union of 3 × 3 boxes that all lie inside \(A \circ C\).
    4. Opening by \(B\) keeps every copy of \(B\) that fits. All of \(A \circ C\) is covered by such copies, so nothing is lost: \((A\circ C)\circ B = A \circ C\).
    General rule. If \(C\) is "open with respect to \(B\)" (\(C \circ B = C\)), then opening by \(C\) then \(B\) = opening by \(C\). The bigger box wins.

    Connected components and reconstruction

    Labelling one component (this is just BFS):

    X ← {x0}                // one seed pixel in A

    Morphological reconstruction generalises this. Input: a marker \(F\) and a mask \(G\).

    \[ D_G(F) = (F \oplus B) \cap G, \qquad R_G(F) = \text{repeat } D_G \text{ until stable} \]

    Result: every component of \(G\) that touches the marker, kept whole.

    • Opening by reconstruction: \(R_A(A \ominus B)\). Erode to kill small things, then regrow survivors to their exact original shape (no rounding). Example: keep only tall letters using a 51 × 1 SE.
    • Hole filling: marker = image border, mask = \(A^c\). Reconstruct the background reachable from the border, then complement.
    • Border clearing: \(A - R_A(\text{border pixels})\).
    • Hysteresis thresholding: marker = strong threshold, mask = weak threshold.
    Trap. During reconstruction, dilate with the elementary 3 × 3 SE, not the big SE you eroded with.

    Distance transform, skeletons, granulometry

    • Distance transform \(D_A(p)\) = distance from \(p\) to the nearest background pixel. Repeated erosion by the cross gives D₄; by the 3 × 3 box gives D₈.
    • Medial axis = points with two or more nearest boundary points = the "ridges" of \(D_A\).
    • Medial axis transform = medial axis with intensity \(D_A\). It stores local thickness and can rebuild the shape.
    • Skeleton by thinning: peel boundary pixels without breaking connectivity.
    • Granulometry: open with SEs of growing size; count pixels left. Big drops = many objects of that size. It gives a size distribution.

    Prove \((A \ominus B) \ominus C = A \ominus (B \oplus C)\).

    Erosion = min, dilation = max

    For a gray image \(f\) and a flat SE \(b\) (just a set of offsets):

    So erosion is a min filter and dilation is a max filter. Erosion makes bright regions shrink and dark regions grow.

    Quiz 3 Q2, solved: the river network

    Satellite image. Rivers: dark curves, width 1 to 20 px. Land: lighter, smoothly varying. Get (i) rivers bright, land ≈ black; (ii) only river parts with width ≥ 5 bright.

    (i) Bottom-hat with a big SE

    Use a disk (or square) of diameter larger than 20 px, say 25. Compute \(g = (f \bullet b) - f\).

    • Closing fills every dark curve narrower than the SE, so \(f\bullet b\) ≈ the land surface with the rivers "paved over".
    • Land is smooth, so closing barely changes it: \(g \approx 0\) on land.
    • On rivers, \(f\bullet b\) is land-bright but \(f\) is dark, so \(g\) is large.

    (ii) Then open with a 5 px disk

    In \(g\) the rivers are bright curves. Opening with a disk of diameter 5 removes bright parts narrower than 5 px and keeps wider parts: \(h = g \circ b_5\).

    Why "negate the image" lost marks. Land intensity varies a lot. In \(L - 1 - f\), dark land patches become bright too. Land is not "close to black". The SE-based hat transform removes the slow background; negation does not.
    Opening vs. opening by reconstruction here. Plain opening is right for (ii). Reconstruction would regrow thin branches that touch a thick river, which we do not want.

    Gray reconstruction, h-maxima, granulometry

    • Geodesic dilation: \(D_g(f) = (f \oplus b) \wedge g\) (\(\wedge\) = pointwise min). Repeat until stable. Grows bright regions of \(f\) but never above \(g\).
    • Opening by reconstruction: \(R_f(f \ominus b)\). Removes small bright objects but rebuilds big ones exactly.
    • h-maxima: \(R_f(f - h)\). Removes peaks less than \(h\) high above their surroundings.
    • h-domes: \(f - R_f(f-h)\). The peak tops that were cut off. Good blob detector.
    • Regional maxima: flat connected regions whose neighbours are all lower.
    • Gray granulometry: open with growing SEs, track \(\sum f\). Works without thresholding.

    Compression basics: entropy and fidelity

    Post-minorDeck 18

    Why compression is possible

    Raw size of an M × N image, C channels, k bits each: \(MNCk\) bits. We can do much better because images have redundancy.

    • Coding redundancy: not every value needs k bits. Common values can get short codes. (Huffman, arithmetic.)
    • Spatial redundancy: neighbours are similar. Store "same as before" cheaply. (Run-length, prediction, transforms.)
    • Irrelevant information: details the eye does not notice can be thrown away. This is lossy.
    \[ C = \frac{\text{bits before}}{\text{bits after}}, \qquad R = 1 - \frac{1}{C} \]

    \(C\) is the compression ratio. \(R\) is the relative redundancy (fraction of the data that was "wasted").

    No free lunch. No method can shrink every image. There are \(2^{MNCk}\) possible images but fewer than \(2^{MNCk}\) shorter bit strings (pigeonhole). Compression works only because real images are a tiny, structured subset.

    Information and entropy

    The information in an event is how surprised you are:

    \[ I(E) = -\log_2 P(E) \text{ bits} \]

    \(P = 1\): 0 bits (no surprise). \(P = 1/4\): 2 bits.

    A memoryless source emits symbols \(a_1 \dots a_J\) independently with fixed probabilities. Its entropy is the average information per symbol:

    \[ H = -\sum_{j} P(a_j)\log_2 P(a_j) \]

    Useful facts

    • \(J\) equally likely symbols: \(H = \log_2 J\). This is the maximum.
    • One symbol with probability 1: \(H = 0\).

    Worked example and Shannon's bound

    An 8-bit image uses only 4 values:

    value87128186255
    P0.250.470.250.03
    code011000001
    \[ H = -(2\times 0.25\log_2 0.25 + 0.47\log_2 0.47 + 0.03\log_2 0.03) \approx 1.66 \text{ bits} \]

    The variable-length code above averages \(0.25\cdot2 + 0.47\cdot1 + 0.25\cdot3 + 0.03\cdot3 = 1.81\) bits. Compression ratio vs 8 bits: \(8/1.81 \approx 4.4\).

    Shannon's noiseless coding theorem. A memoryless source with entropy \(H\) needs at least \(H\) bits per symbol on average. No lossless code beats it.
    But images are not memoryless. Neighbouring pixels are correlated. So first transform (runs, prediction errors, DCT), then code. The entropy of the transformed data is often far below the entropy of the raw pixel histogram.

    Measuring quality for lossy compression

    \[ \text{MSE} = \frac{1}{MN}\sum_{x,y}\big(\hat f[x,y]-f[x,y]\big)^2, \qquad \text{PSNR} = 10\log_{10}\frac{I_{\max}^2}{\text{MSE}}\ \text{dB} \]

    Higher PSNR = better. But MSE does not match what eyes see. Contrast stretch, mean shift, blur, JPEG and salt-and-pepper can all have the same MSE yet look very different.

    SSIM (structural similarity)

    Compare two patches \(f, g\) on three things and multiply:

    \[ l = \frac{2\mu_f\mu_g + \epsilon_1}{\mu_f^2+\mu_g^2+\epsilon_1},\quad c = \frac{2\sigma_f\sigma_g + \epsilon_2}{\sigma_f^2+\sigma_g^2+\epsilon_2},\quad s = \frac{\sigma_{fg} + \epsilon_3}{\sigma_f\sigma_g+\epsilon_3} \]

    SSIM \(= l\cdot c\cdot s \le 1\). Computed on small patches and averaged. A mean shift keeps structure, so SSIM stays high (0.99). Blur and JPEG damage structure, so SSIM drops (≈0.7).

    Encoders, decoders and standards

    • Encoding is usually much more expensive than decoding (searching for matches, motion vectors, etc).
    • A standard usually only fixes the decoder. Many encoders can exist for one decoder.
    • JPEG = compression standard. GIF = file format with its own compression (LZW). TIFF = container that can hold many codecs.
    Story worth one line in an answer. Xerox scanners (2013) swapped digits in documents. The bug was in their JBIG2 encoder (bad symbol matching), not in the standard, because the standard only specifies decoding.

    Symbol coding and spatial redundancy

    Huffman coding

    Give short codes to common symbols. Build a tree bottom-up:

    1. List symbols with probabilities.
    2. Merge the two smallest into one node (add probabilities).
    3. Repeat until one node is left.
    4. Label branches 0/1. A symbol's code = path from root to its leaf.

    Average length \(= \sum p_i \ell_i = .4(1)+.3(2)+.1(3)+.1(4)+.06(5)+.04(5) = 2.2\) bits. Entropy \(= 2.14\) bits. Very close.

    Why Huffman is good, and where it fails

    • Prefix-free / instantaneous: no code is the start of another, so you decode left to right with no lookahead.
    • Uniquely decodable: only one way to split a bit string.
    • Optimal among codes that encode one symbol at a time: \(H \le \bar\ell < H + 1\).

    Decode 010100111100 with the tree above: 01010·011·1·1·00 → a3 a1 a2 a2 a6.

    Failure case. \(P(a_1) = 0.9, P(a_2) = 0.1\). \(H \approx 0.47\) bits, but every Huffman code word is at least 1 bit, so 1 bit/symbol. Wasteful by 2×.

    Fix 1: code pairs of symbols. Probabilities .81, .09, .09, .01 → lengths 1, 2, 3, 3 → \(1.29\) bits per pair = \(0.645\) bits/symbol.

    Fix 2: arithmetic coding (next).

    Golomb coding: a ready-made code for geometric distributions (small numbers very likely), e.g. run lengths or prediction errors. No tree needed.

    Arithmetic coding

    Encode the whole message as one number in [0, 1). Each symbol shrinks the current interval in proportion to its probability.

    low = 0, high = 1
for each symbol s:
    w = high − low
    high = low + w · cumHigh(s)
    low  = low + w · cumLow(s)
output any number in [low, high)
    • Final width = product of the symbol probabilities. Bits needed \(\approx -\log_2(\text{width})\) = total information. So it approaches the entropy, even for \(p = 0.9\).
    • Not a block code: one code word for the whole message.
    • Practice: reserve an end-of-message symbol (or send the length). Use careful finite-precision rounding. Probabilities can be adaptive or context-based, as long as the decoder updates them the same way.

    Spatial filters: smoothing and sharpening

    Pre-minorDeck 04, 05 · Minor Q2

    Correlation and convolution

    A linear filter replaces each pixel by a weighted sum of its neighbours. The weights form the kernel \(w\).

    \[ \text{correlation: } (w\star f)(x) = \sum_s w(s)\,f(x+s) \qquad \text{convolution: } (w*f)(x) = \sum_s w(s)\,f(x-s) \]

    Convolution = correlation with a flipped kernel. For symmetric kernels they are the same.

    Impulse test

    f0 0 0 1 0 0 0 0
    w1 2 4 2 8
    correlation0 8 2 4 2 1 0 0
    convolution0 1 2 4 2 8 0 0

    Convolving with an impulse gives back a copy of the kernel. Correlation gives a flipped copy.

    • Convolution is commutative, associative, distributive. Correlation is not commutative or associative.
    • Big kernel \(m\times n\) on an \(M\times N\) image: \(O(MNmn)\). If separable (\(w = u v^T\)), do rows then columns: \(O(MN(m+n))\).

    Smoothing: box, Gaussian, median

    • Box (mean): all weights \(1/mn\). Simple but makes blocky artefacts.
    • Gaussian: weights \(\propto e^{-(s^2+t^2)/2\sigma^2}\). Smooth, separable. Use kernel width ≈ \(6\sigma\).
    • Median: sort the window, take the middle. Nonlinear. Best for salt-and-pepper noise. Keeps edges sharp but rounds corners.
    • Min / max: also order-statistic filters. (They are gray erosion / dilation.)
    window with salt
    mean ≈ 37 (smeared)
    median = 10 (fixed)

    Mean of \(mn\) noisy values cuts noise variance by \(mn\) (if the region is truly flat).

    Bilateral filter: smooth but keep edges

    \[ g(p) = \frac{1}{W(p)}\sum_q G_s(\|p-q\|)\;G_r(|f(p)-f(q)|)\;f(q) \]
    • \(G_s\): spatial Gaussian. Near pixels count more.
    • \(G_r\): range Gaussian. Pixels with similar intensity count more.
    • \(W(p)\) = sum of all weights, so they add to 1.

    Across an edge the intensity jumps, so \(G_r \approx 0\) and those pixels are ignored. Result: flat areas get smoothed, edges stay sharp.

    • Not linear: weights depend on the image itself.
    • Cross (joint) bilateral: take \(G_r\) from a flash photo (clean edges) but average the no-flash photo.
    • HDR tone mapping: split \(f = \) base (bilateral) + detail, compress only the base.

    Derivatives and sharpening

    \[ f'(x) \approx f(x+1)-f(x), \qquad f''(x) \approx f(x+1) - 2f(x) + f(x-1) \]
    Laplacian ∇²
    sharpen: f − ∇²f
    Sobel ∂/∂x
    • Laplacian sharpening: \(g = f - c\,\nabla^2 f\) (with the −4 centre kernel). Adds back edges.
    • Unsharp masking: \(g = f + k\,(f - f_{\text{blur}})\). \(k = 1\) unsharp, \(k > 1\) high-boost.
    • Gradient magnitude \(\sqrt{f_x^2 + f_y^2}\) for edges (more in the edge chapter).

    Derivative kernels sum to 0 (flat input → 0 output). Smoothing kernels sum to 1 (flat input unchanged).

    Template matching

    Find where a small template \(w\) appears in image \(f\).

    • Plain correlation \(\sum w f\): fooled by bright regions.
    • SSD \(\sum (w - f)^2\): fooled by lighting changes.
    • Normalized cross-correlation (subtract means, divide by norms). Invariant to brightness offset and contrast scale. Peak = match.
    \[ g(x) = \frac{\sum_s (w(s)-\bar w)(f(x+s)-\bar f_x)}{\sqrt{\sum_s (w(s)-\bar w)^2\,\sum_s (f(x+s)-\bar f_x)^2}} \]

    Predictive coding

    Post-minorDeck 20 · Quiz 4 Q1

    Store the surprise, not the value

    Guess each sample from earlier samples: \(\hat f[n]\). Store only the prediction error:

    \[ e[n] = f[n] - \hat f[n] \]

    The decoder makes the same guess and adds the error back. If guesses are good, errors are small and cluster around 0. A peaked histogram has low entropy, so Huffman/arithmetic coding of \(e\) needs few bits.

    Example: JPEG stores each block's DC coefficient as the difference from the previous block's DC.

    Which predictor?

    1D linear predictor: \(\hat f[n] = \text{round}\big(\sum_i \alpha_i f[n-i]\big)\). In 2D you can also use the row above.

    Paeth example: a = 100, b = 110, c = 105 → \(p = 105\) → c is closest → predict 105.

    Key idea for exam questions. A predictor that uses \(f[n-1]\) is exact on constant regions. A predictor \(2f[n-1] - f[n-2]\) (linear extrapolation) is exact on constant-slope regions.

    Quiz 4 Q1, solved

    Length-n signal, k ≪ n regions of constant slope, jumps at boundaries. Predict \(\hat f(x) = f(x-1)\), then Huffman. Best compression ratio with 8 bits/sample?

    1. Inside a region of slope \(s\), \(e = s\). So we get \(k\) values, each repeated about \(n/k\) times. Plus \(k - 1\) jump values that occur once each.
    2. Probabilities: about \(1/k\) for each slope value, \(1/n\) for each jump value.
    3. Entropy: \[ H \approx k\cdot\tfrac1k\log k + (k-1)\cdot\tfrac1n\log n = \log k + \tfrac{k-1}{n}\log n \]
    4. Since \(k \ll n\), the second term is tiny. Ratio \(\approx 8 / \log_2 k\).
    Bonus insight. With \(\hat f = 2f(x-1) - f(x-2)\), the error is 0 inside every region. Only ~2 nonzero values per boundary. Far better.
    Huffman caveat. Huffman needs ≥ 1 bit per symbol, so the true Huffman ratio is at most 8. "Best possible" here means the entropy bound.

    Lossy predictive coding

    Quantize the error to save more bits: \(\dot e = Q(f - \hat f)\). Now the decoder only knows \(\dot f = \hat f + \dot e\), not \(f\).

    The encoder must predict from decoded values \(\dot f\), exactly like the decoder. If it used the true \(f\), the two would drift apart and errors would pile up.

    Delta modulation

    The simplest lossy predictor. 1 bit per sample.

    \[ \hat f[n] = \alpha\,\dot f[n-1], \qquad \dot e[n] = \begin{cases}+\zeta & e[n] > 0\\ -\zeta & \text{else}\end{cases}, \qquad \dot f[n] = \hat f[n] + \dot e[n] \]

    Example: \(\zeta = 10\), \(\alpha = 1\), \(f = [3, 6, 9, 12]\), start \(\dot f[-1] = 0\).

    f36912
    f̂010010
    e3−492

    ḟ1001020
    • Granular noise: on flat parts the output jitters by ±ζ.
    • Slope overload: if \(f\) rises faster than ζ per sample, the output lags behind.

    Big ζ: less overload, more granular noise. Small ζ: the opposite.

    Video: predict from the previous frame

    • Temporal prediction: \(\hat f[x,y,t] = f[x,y,t-1]\). Great for static scenes, bad for fast motion.
    • Motion compensation: for each macroblock, search the previous frame for the best-matching block at some offset. Store the motion vector + the residual.

    Example from slides: plain frame difference had std 12.73 and entropy 4.17 bits. Motion-compensated residual: std 5.62, entropy 3.04 bits.

    Encoding (the search) is expensive. Decoding (copy block + add residual) is cheap. Some frames are predicted from a later frame, so that frame must be sent first.

    Quiz 4 Q1 variantSame signal but piecewise constant (k flat regions). Predictor \(f(x-1)\). Best compression ratio?

    Errors are 0 everywhere except \(k-1\) jumps. \(P(0) \approx 1\), so \(H \approx \frac{k-1}{n}\log n\) (plus a tiny term for the zeros). Ratio \(\approx 8n / ((k-1)\log n)\): huge. (Huffman would cap at 8; RLE or arithmetic coding gets close to the bound.)

    Run delta modulation with \(\zeta = 4\), \(\alpha = 1\), start 0, on \(f = [1, 2, 10, 20]\). Where does slope overload happen?
    Answer

    n=0: f̂=0, e=1 → +4, ḟ=4. n=1: f̂=4, e=−2 → −4, ḟ=0. n=2: f̂=0, e=10 → +4, ḟ=4. n=3: f̂=4, e=16 → +4, ḟ=8.

    Why must a lossy predictive encoder use the decoded signal for prediction?
    Answer

    The decoder only has \(\dot f\). If the encoder predicted from \(f\), its prediction would differ from the decoder's, and the quantization errors would accumulate (drift) at the decoder. Using \(\dot f\) keeps both in sync, so the reconstruction error at each sample is just that sample's quantization error.

    Edge detection and the Hough transform

    Post-minorDeck 21, 22 · Quiz 4 Q2, Q4

    What derivatives do at an edge

    An edge is where intensity changes fast. Real edges are blurred steps: ramps. (A smoothing filter applied to a step gives a ramp.)

    • Size of \(f'\) tells you an edge is there.
    • The zero crossing of \(f''\) tells you exactly where. Its sign tells you which side is dark.
    • Roof edge (thin line) = two ramps back to back.
    Noise. Derivatives amplify noise badly (second derivative even more). Always smooth first. Steps: (1) smooth, (2) find candidate edge points, (3) localize/thin them.

    Gradient and Sobel

    \[ \nabla f = \begin{bmatrix} \partial f/\partial x \\ \partial f/\partial y\end{bmatrix}, \quad \|\nabla f\| = \sqrt{f_x^2 + f_y^2}, \quad \alpha = \tan^{-1}(f_y / f_x) \]
    • The gradient points across the edge (perpendicular to the edge direction).
    • Derivative in direction \(d\): \(\nabla f \cdot d\).
    Roberts
    Sobel (one direction)
    Sobel (other)

    Sobel = central difference in one direction × small smoothing [1 2 1] in the other. Simple detector: smooth, Sobel, threshold \(\|\nabla f\|\). Edges come out thick.

    Marr-Hildreth: zero crossings of LoG

    Convolve with the Laplacian of Gaussian, then mark zero crossings.

    \[ g = \nabla^2 G * f = \nabla^2 (G * f), \qquad \nabla^2 G(x,y) = \frac{x^2+y^2-2\sigma^2}{\sigma^4}\,e^{-\frac{x^2+y^2}{2\sigma^2}} \]
    • \(\sigma\) sets the scale: big σ finds only big, strong edges.
    • Fast: Gaussian (separable) then a 3 × 3 Laplacian. Keep Gaussian width ≥ 6σ.
    • Zero crossing at a pixel: sign of \(g\) differs between opposite neighbours (left/right, up/down, or diagonals).
    • Keep only strong edges: also need \(|g(x+1) - g(x-1)| >\) threshold.
    • Why \(\nabla^2(G*f) = (\nabla^2 G)*f\): derivatives commute with convolution, \(\frac{d}{dx}(g*f) = \frac{dg}{dx}*f\).

    Quiz 4 Q2, solved: dark line on white

    One column of the image: white, a narrow dark dip, white. Smooth with Gaussian h to get g. Sketch g, dg/dx, ∇²g. Mark Marr-Hildreth edges.

    • \(g\) is an upside-down bell.
    • \(dg/dx\): negative on the left wall of the dip, zero at the bottom, positive on the right wall.
    • \(\nabla^2 g\): the dip bottom curves upward, so \(\nabla^2 g > 0\) in the middle and \(< 0\) on the shoulders.
    • Two zero crossings, one on each side of the line. Those are the edges (the line's two borders), where \(|dg/dx|\) peaks.

    Canny edge detector

    1. Smooth: \(g = G * f\).
    2. Gradient magnitude and direction of \(g\).
    3. Non-maximum suppression: look at the two neighbours along the gradient direction. If either has bigger \(\|\nabla g\|\), set this pixel to 0. Edges become 1 pixel thin.
    4. Hysteresis thresholding: high threshold → strong pixels; low threshold → weak pixels. Keep weak pixels only if connected to strong ones.

    Canny is near-optimal for a step in Gaussian noise (in 1D it is "find maxima of \(G' * f\)"). Compared with Marr-Hildreth: thinner, cleaner, fewer spurious loops.

    Hough transform for lines

    Edge pixels are scattered. Which straight lines pass through many of them? Use the normal form:

    \[ x\cos\theta + y\sin\theta = \rho \] 
    A[ρ, θ] = 0
for each edge pixel (x, y):
    for each θ_j:
        ρ = x cos θ_j + y sin θ_j
        A[round(ρ), j] += 1
lines = peaks of A
    • Point in image ↔ curve in parameter space. Line in image ↔ point in parameter space.
    • Normal form avoids infinite slopes (vertical lines are fine).
    • Speed-ups: use the gradient direction, so each pixel votes only for θ near its gradient angle; weight votes by \(\|\nabla f\|\). Progressive probabilistic Hough: add pixels randomly, report a line once its bin is significant, then remove its pixels.

    Hough for circles, and Quiz 4 Q4

    General circle \((x-a)^2 + (y-b)^2 = r^2\) has 3 parameters → 3D accumulator. Too slow. Two tricks:

    • Fix r: for each edge pixel, loop over θ: \(a = x - r\cos\theta,\ b = y - r\sin\theta\). 2D accumulator.
    • Use the gradient: the centre lies along the gradient line, so loop only over r: \(a = x \mp r\cos\alpha\), \(b = y \mp r\sin\alpha\).

    Quiz 4 Q4: circles tangent to the x-axis

    Centre \((c, d)\), radius \(d\). Condition \((x-c)^2 + (y-d)^2 = d^2\). Expand:

    Answer

    \(\rho = 0\), so \(x\cos\theta + y\sin\theta = 0\) → \(\theta = \operatorname{atan2}(-x, y)\) (mod π). Each pixel votes once in a 1D accumulator over θ.

    Sketch g, g′ and ∇²g for a single upward step edge smoothed by a Gaussian. Where is the Marr-Hildreth edge?
    Answer

    g is a ramp (S-curve). g′ is a bump (positive peak) at the edge. g″ is positive before the edge, negative after (or vice versa), with one zero crossing exactly at the peak of g′. That zero crossing is the edge.

    Why do we use the normal form \(\rho = x\cos\theta + y\sin\theta\) and not \(y = mx + c\)?
    Answer

    \(m\) is unbounded (infinite for vertical lines), so the accumulator cannot cover it. \(\theta \in [0, \pi)\) and \(|\rho| \le\) image diagonal are both bounded.

    Region segmentation: thresholds and clusters

    Post-minorDeck 22

    Segmentation = labelling every pixel

    Split the M × N pixels into classes, usually foreground \(C_1\) and background \(C_2\). Edge detection looks for differences; region segmentation looks for similarity.

    If we know each class's intensity distribution \(p_1(z), p_2(z)\), give a pixel with value \(z\) to the class with the larger likelihood \(p_i(z)\). This is maximum likelihood classification.

    Thresholding

    • Global: one \(T\) for the whole image. \(g = 1\) if \(f > T\).
    • Multiple: \(T_1 < T_2\) give 3 classes.
    • Variable / local: \(T(x,y)\) from the local mean and std, e.g. \(T = m(x,y) + k\,\sigma(x,y)\). Handles uneven lighting.

    Otsu's method: pick T automatically

    Good split: each class is tight (small variances) and the classes are far apart. For threshold \(k\):

    \[ P_1 = \sum_{i\le k} p_i,\quad m_1 = \frac{1}{P_1}\sum_{i\le k} i\,p_i,\quad m_2 = \frac{1}{P_2}\sum_{i>k} i\,p_i \] \[ \sigma_B^2 = P_1(m_1 - m_G)^2 + P_2(m_2-m_G)^2 = P_1P_2(m_1 - m_2)^2 \]
    • Total variance = between-class + within-class: \(\sigma_G^2 = \sigma_B^2 + \sigma_W^2\). \(\sigma_G^2\) is fixed.
    • So maximize \(\sigma_B^2\) ⇔ minimize \(\sigma_W^2 = P_1\sigma_1^2 + P_2\sigma_2^2\).
    • Try every \(k\), keep the best. Fast with running sums of \(P_1(k)\) and \(\sum i p_i\).
    • Separability \(\eta = \sigma_B^2/\sigma_G^2 \in [0,1]\).

    Edge trick. If the object is tiny, its histogram peak is invisible. Run Otsu only on pixels near strong edges (high gradient or |Laplacian|). Then both classes are equally represented.

    Multiple thresholds: maximize \(\sum_k P_k (m_k - m_G)^2\) over all choices of \(k_1 < k_2 < \dots\)

    k-means clustering

    Treat each pixel's value (or colour) as a point \(z_i\). Find \(k\) means minimizing the within-cluster sum of squares:

    \[ \text{WCSS} = \sum_{i=1}^{n}\|z_i - m_{a_i}\|^2 \]
    1. Guess means \(m_1, \dots, m_k\).
    2. Assign each point to its nearest mean.
    3. Move each mean to the average of its points.
    4. Repeat 2–3 until the means stop moving.
    • k-means = maximum likelihood if clusters are Gaussians with equal variance (log-likelihood ∝ −WCSS).
    • For gray images with k = 2, k-means and Otsu minimize the same thing (WCSS ∝ \(\sigma_W^2\)). Otsu finds the global optimum by trying all k. k-means can get stuck in a local minimum, but it extends easily to colour and many clusters.

    Superpixels with SLIC

    k-means on position + colour: \(z_i = [x, y, r, g, b]\). Clusters become small compact patches that follow edges.

    1. Seed centres on a grid with spacing \(s\). Nudge each to the lowest-gradient pixel in its 3 × 3 neighbourhood (so seeds do not sit on edges).
    2. Assign each pixel to the nearest centre, searching only centres within a \(2s \times 2s\) window. (This makes it fast: \(O(N)\).)
    3. Update centres, repeat.
    \[ D = \sqrt{(d_c/c)^2 + (d_s/s)^2} \]

    \(d_c\) = colour distance, \(d_s\) = pixel distance. \(c\) trades off compactness vs. sticking to colour. Superpixels give a small over-segmentation to feed into k-means, graph cuts, etc.

    Intelligent scissors

    The user clicks a seed point. As the mouse moves, the tool draws the shortest path from seed to mouse through a graph of pixels (8 neighbours each). Dijkstra makes it fast.

    Edge weights must be low along image edges:

    \[ w(p,q) = \lambda_Z w_Z(q) + \lambda_G w_G(q) + \lambda_D w_D(p,q) \]
    • \(w_Z = 0\) if \(q\) is a Laplacian zero crossing (on an edge), else 1.
    • \(w_G\) small when \(\|\nabla f(q)\|\) is large.
    • \(w_D\) small when the step \(p\to q\) runs along the edge (perpendicular to both gradients), and the gradients agree. Smooth paths.

    Give a case where k-means with k = 2 on intensity fails, but Otsu works.
    Answer

    Bad initialization: if both initial means start inside the same mode (e.g. both in the background), k-means can converge to splitting the background into two and lumping the object with one half. Otsu checks every threshold, so it always finds the global best.

    Why does SLIC only search a \(2s\times 2s\) window?
    Answer

    Centres are about \(s\) apart, so a pixel's nearest centre must be within about \(s\) in each direction. Limiting the search makes each iteration \(O(N)\) instead of \(O(Nk)\), and keeps superpixels compact.
