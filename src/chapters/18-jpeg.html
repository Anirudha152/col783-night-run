Block transform coding and JPEG

Post-minorDeck 19, 20

The idea

Split the image into n × n blocks. Transform each block. Most energy lands in a few coefficients. Keep those (roughly), drop or coarsely store the rest.

Keep only \(1/k\) of the coefficients → compression ratio ≈ \(k\).

If the transform is orthogonal, the error equals what you threw away:

\[ \|G - \hat G\|^2 = \|T - \hat T\|^2 = \text{sum of squares of dropped coefficients} \]

Which transform, which block size?

  • We want a transform that packs the most energy into the fewest coefficients.
  • The best one depends on the data: Karhunen–Loève transform (= PCA of the blocks). Must be computed and sent per image.
  • The DCT is fixed and nearly as good (optimal-ish for images modelled as a first-order Markov process). It also has no border jumps (see Quiz 3 Q3).
  • Bigger blocks: more compression, more compute; gains flatten after about 8 × 8.
  • JPEG uses 8 × 8. HEVC uses variable 16 × 16 to 64 × 64.
  • Strong compression → visible blocking artifacts at block borders.

Bit allocation and the quantization matrix

  • Zonal coding: keep coefficients at fixed positions (the ones with highest variance over all blocks), same for every block.
  • Threshold coding: keep coefficients bigger than a threshold. Positions vary per block, mostly at low frequency.

In practice: store every coefficient, but with precision that depends on its position:

\[ \hat T[u,v] = \operatorname{round}\!\Big(\frac{T[u,v]}{Z[u,v]}\Big) \]
  • Big \(Z[u,v]\) (high frequencies) → coarse. If \(|T| < Z/2\), it becomes 0.
  • Change quality by scaling \(Z\) up or down.

Example: \(T(0,0) = 260, Z = 16 \to 16\). \(T(0,1) = -29, Z = 11 \to \text{round}(-2.64) = -3\). \(T(5,5) = 7, Z = 80 \to 0\).

Decoder: \(\tilde T = \hat T \cdot Z\), then inverse DCT.

JPEG step by step

  1. Split into 8 × 8 blocks.
  2. Subtract 128 (= L/2) so values centre on 0.
  3. 2D DCT.
  4. Quantize with \(Z\).
  5. Zigzag scan (low → high frequency), so the zeros bunch up at the end.
  6. DC coefficient: code the difference from the previous block's DC (predictive coding).
  7. AC coefficients: run-length of zeros + value, then Huffman. End-of-block code for the trailing zeros.

Colour in JPEG: YCbCr and chroma subsampling

Eyes are much more sensitive to brightness detail than to colour detail. So:

  1. Convert RGB → Y'CbCr (\(K_R = 0.299, K_G = 0.587, K_B = 0.114\)).
  2. Subsample Cb and Cr.
  3. Code Y', Cb, Cr separately with the 8 × 8 DCT pipeline.

J:a:b on a J × 2 block: J = width of the block, a = chroma samples in row 1, b = chroma samples in row 2. Filled cells = where a chroma sample is kept.

4:2:0: Y full (1) + Cb ¼ + Cr ¼ = 1.5 samples/pixel instead of 3. Half the raw data before any DCT.

Wavelet coding (JPEG 2000)

  • No blocks: take a multi-level wavelet transform of the whole image (CDF 9/7 wavelets).
  • Quantize coefficients (rounded towards zero), code them bit-plane by bit-plane.
  • No blocking artifacts. At high compression it blurs instead. Better quality than JPEG at the same ratio, e.g. at C = 52.

Exam-style practice

Quantize the DCT coefficients \([-415, 30, -12, 4]\) with \(Z = [16, 11, 10, 16]\). Then dequantize. What is the squared error?
Answer

\(\hat T = \text{round}([-25.9, 2.73, -1.2, 0.25]) = [-26, 3, -1, 0]\). Dequantized: \([-416, 33, -10, 0]\). Errors: \(1, 3, 2, 4\) → squared sum \(1+9+4+16 = 30\). Orthogonal DCT, so the pixel-domain squared error is also 30.

Why does JPEG code DC coefficients differentially but AC coefficients with run-lengths?
Answer

DC = block average; neighbouring blocks have similar averages, so the difference is small (predictive coding). AC coefficients after quantization are mostly zero at high frequencies, so zigzag + run-lengths of zeros captures them compactly.

Why would using the DFT instead of the DCT for 8 × 8 blocks be worse?
Answer

The DFT assumes each block repeats, creating jumps at block edges whenever the left and right (or top and bottom) sides differ. Those jumps need many high-frequency coefficients, which then get quantized → more error and visible ringing. The DCT's mirror extension has no jump. Also DFT coefficients are complex.

Cheat sheet · JPEG

  • Block → transform → quantize (lossy) → entropy code
  • Keep 1/k coeffs → \(C\approx k\)
  • Orthogonal: \(\|G-\hat G\|^2 = \sum\) dropped coeffs²
  • KLT/PCA optimal (data-dependent); DCT ≈ optimal
  • \(\hat T = \text{round}(T/Z)\); zero if \(|T|<Z/2\); scale Z for quality
  • JPEG: 8×8, −128, DCT, Z, zigzag, DC diff, RLE+Huffman
  • 4:2:0: 1.5 samples/px vs 3
  • J:a:b = width, chroma row 1, chroma row 2
  • JPEG 2000: DWT CDF 9/7, bit planes, no blocks
